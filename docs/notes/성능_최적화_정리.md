# 성능 최적화 정리

> git 히스토리(전체 1105 커밋 중 성능 관련 47개)와 실제 코드를 기준으로, 이 프로젝트에서 진행한 성능 최적화 작업을 카테고리별로 정리한 것.

## 1. DB/쿼리 최적화 — 좌표 기반 매물 검색

**파일**: `backend/src/main/resources/com/salgosipo/property/mapper/PropertyMapper.xml`, `backend/src/main/resources/sql/table.sql`

- 매물 위경도 컬럼(`property_latitude`, `property_longitude`)에 복합 B-Tree 인덱스(`idx_properties_location`) 적용.
- 초기엔 `ST_Distance_Sphere`(구면삼각법) 하나로만 반경 검색 → 인덱스를 못 타는 풀스캔에 가까웠음.
- **"사각형 바운딩 박스로 1차 B-Tree 필터링 → 정밀 거리 계산은 후처리"** 2단계 패턴으로 전환 (`4920a57`, `44bdd2a`, `7d25237`):
  ```sql
  AND p.property_latitude BETWEEN (lat - radius/111.0) AND (lat + radius/111.0)
  AND p.property_longitude BETWEEN (lng - radius/88.0) AND (lng + radius/88.0)
  AND ST_Distance_Sphere(POINT(lng, lat), POINT(p.longitude, p.latitude)) <= radius*1000
  ```
  (1도 ≈ 위도 111km, 경도 88km(서울 위도 기준 cos 보정))
- 지도 뷰포트 이동 시엔 `<choose>`로 분기해 반경 계산 없이 **뷰포트 사각형(swLat/swLng/neLat/neLng) BETWEEN 조회만** 수행 (`7d25237`) — 팬/스크롤마다 구면거리 계산을 생략.
- 정렬 시 `LIMIT 500`으로 대량 결과 조회 방지, 응답 DTO에서 미사용 컬럼(썸네일 서브쿼리, 하드코딩 텍스트 등) 제거로 페이로드 경량화 (`44bdd2a`).

## 2. 공간 색인 — 안전시설(CCTV/보안등/경찰서) 인메모리 그리드 인덱스

**파일**: `backend/src/main/java/com/salgosipo/safety/repository/SafetyFacilityRepository.java`

- CCTV/가로등/경찰시설 원본 데이터를 DB 테이블 대신 classpath CSV로 서버 기동 시 1회만 로드.
- **0.01도(약 1.1km) 격자 셀 단위 해시맵**(`Map<GridCell, List<SafetyFacilityVO>>`)을 애플리케이션 메모리에 구축 (`toCellIndex = floor(좌표 / 0.01)`).
- `findInBounds(minLat, maxLat, minLng, maxLng)` 호출 시 DB 쿼리 없이 필요한 셀만 순회해 후보를 뽑고 실제 bbox로 2차 필터링 — R-tree/PostGIS 없이 순수 자바 해시맵으로 공간 인덱싱 구현.
- `SafetyServiceImpl.calculateFastLocalSafety()`(`7d25237`)에서 이 인덱스로 목적지-매물 bbox(±0.003도) 안 시설을 즉시 집계해, 외부 라우팅 엔진 호출 없이 CCTV/가로등 개수·경찰서 유무 기반 점수를 로컬에서 즉시 계산.

## 3. 캐싱 계층

**파일**: `CacheConfig.java`, `PropertySearchCondDTO.java`, `SafetyServiceImpl.java`, `MapView.vue`

- **Caffeine 인메모리 캐시**(`propertyList`, `propertyDetail`): 만료 시간을 60분 → 600분(10시간)으로 늘리고 최대 10,000엔트리 유지 (`f2e0f0f`).
- `PropertySearchCondDTO.toCacheKey()`가 검색조건(좌표는 소수점 2자리로 반올림, keyword/필터/정렬 등)을 직렬화해 `@Cacheable` 키로 사용. 좌표를 3자리→2자리로 낮춰 살짝 이동해도 캐시가 재사용되도록 해서 **캐시 히트율 향상** (`44bdd2a`).
- **안전점수 route 캐시**: `SafetyRouteCacheVO` 테이블에 목적지-매물 조합별 계산된 경로/점수를 저장, `SafetySeedBatchService`(`571178f`)가 이미 캐시된 조합은 재계산(=Tmap 재호출)을 스킵하고 새 조합만 배치 처리 — Tmap 호출 제한 문제를 캐싱으로 회피.
- **비동기 백그라운드 DB 캐싱**(`0f7381f`): 도커(Valhalla) 배치 경로 계산 시, 예전엔 계산 직후 동기적으로 `safetyMapper.upsertPropertySafety()`가 끝나야 응답을 줬는데, `CompletableFuture.runAsync()`로 DB 저장을 백그라운드로 분리 — 사용자 응답은 계산 즉시, DB 반영은 비동기로 처리.
- 프론트엔드도 별도 캐시 계층 존재: `MapView.vue`의 `propertyCache = new Map()`(목적지 좌표+반경 키로 매물 목록 인메모리 캐시, 같은 목적지 재조회 시 네트워크 요청 자체 스킵, `5723c48`), 편의시설 필터용 로컬스토리지 캐시 유틸(`06cdf61`, `f8ea1ba`, `1fe0eea`, `6fd1ec7` — 로그인/로그아웃 시 사용자별 캐시 분리·초기화).

## 4. 동시성/병렬처리

**파일**: `PublicDataSyncService.java`

- **실거래가 수집**(`e45b0a1`): 서울 25개 자치구 × 3개월 = 최대 75개 작업을 `parallelStream()`으로 병렬 API 호출 → `ConcurrentLinkedQueue`에 결과 적재 → 100건 단위 배치 INSERT (DB 커넥션 과부하 방지, 순차 처리 대비 시간 대폭 단축).
- **지오코딩 최적화**(`f10882b`): 매물 3,799건 각각 지오코딩하던 방식에서, 실제 고유 건물 주소는 200~400개뿐이라는 점을 이용해 **"중복 주소 제거"**를 먼저 적용(`Set<String>`으로 유니크 주소만 추출) → **50개 전용 스레드풀**(`ExecutorService` + `CompletableFuture`)로 그 주소들만 호출, 결과를 `ConcurrentHashMap`에 캐싱해 원래 매물 리스트에 재매핑. API 호출 횟수를 건수 기준이 아니라 고유 주소 기준으로 줄여 외부 API 호출량을 90% 이상 절감. 이후 100개 단위 배치 UPDATE로 DB 반영.
- **안전점수 배치**: 200개 매물 단위로 `propertyIds.parallelStream()` 병렬 처리 + 위 3번 항목의 비동기 DB 저장 결합.

## 5. 프론트엔드 지도 렌더링

**파일**: `frontend/src/components/map/NaverMap.vue`, `frontend/src/utils/mapClustering.js`

- **마커 HTML 생성 방식 전환**(`eaf74d9`): 마커마다 Vue 컴포넌트(`PropertyPin.vue`, `DestinationPin.vue`)를 `createApp().mount()` 후 `innerHTML` 추출·`unmount()`하던 방식(마커 수백 개면 Vue 앱 인스턴스를 수백 번 생성/파괴 → 렉 발생)을 **순수 문자열 템플릿 리터럴**로 교체해 Vue 런타임 오버헤드 제거.
- **bounds 필터링 최적화**: 매물마다 `bounds.hasLatLng(new naver.maps.LatLng(...))`(SDK 객체 생성 + 메서드 호출) 호출하던 것을, SW/NE 좌표를 미리 숫자로 꺼내 **단순 사칙비교**(`lat >= minLat && lat <= maxLat`)로 교체.
- **마커 Diffing + 시분할 렌더링**(`5723c48`): 렌더링마다 마커 전체 삭제 후 재생성하던 방식을, `Map<key, marker>`로 기존 마커를 유지하며 **불필요해진 마커만 즉시 삭제(동기)**, **새로 필요한 마커만 `requestAnimationFrame`으로 25개씩 청크 단위 비동기 생성**(타임 슬라이싱)하도록 변경 — 메인 스레드 블로킹 없이 지도 팬/줌 시 프레임 드랍 방지.
- **격자 클러스터링**: `mapClustering.js`의 `getClusteredMarkers()`가 줌 레벨 기준 grid 좌표(`floor(lng/gridSize)`, `floor(lat/gridSize)`)로 매물을 묶어 클러스터 마커로 축약 — 저줌 레벨에서 수백 개 매물을 몇 개 클러스터 핀으로만 렌더링.
- **이소크론/미지원구역 시각화**(`6bebe3b`, `d798ae9`): `districtPolygonOverlay.js`, `hybridRouteOverlay.js`에서 도보 경로 지원/미지원 자치구를 폴리곤으로 미리 분할해 오버레이하는 방식으로 렌더링 로직 정리.

## 6. 라우팅 엔진 전환 (Docker)

- Tmap 유료/제한 호출 → Valhalla(도보)/MOTIS(대중교통) Docker 컨테이너로 대체, 실패 시 Tmap 자동 폴백 (`RoutingEngineRouter.java`). 자세한 내용은 [DOCKER_라우팅_구조.md](DOCKER_라우팅_구조.md) 참고.
- `RoutingConfigLoader.java`(`0f7381f`): 환경변수 → JVM 시스템 프로퍼티 → properties 파일 → Spring `${KEY:DEFAULT}` 템플릿까지 자동 파싱하도록 통합해, 로컬/Railway 배포 환경 전환 시 설정 코드 중복 제거.
